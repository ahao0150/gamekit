# 公共版与私有版同步维护

两个仓库分别保留自己的分支、历史、远端与业务目录。共享修复只包含框架、模板和公共文档；不要用目录镜像或整仓覆盖同步。

1. 先记录双方HEAD、分支、未提交文件及远端；私有仓库可能同时配置公共远端，推送前必须确认目标。
2. 在双方独立修复分支应用同一组公共文件改动；有基线差异时按语义应用，保留私有组件及其测试。
3. 双方分别运行typecheck、test、lint与verify-platform；受本地未提交游戏影响的失败单独列出。
4. 只暂存本次明确修改的文件。提交前检查cached diff及文件列表，排除games、锁文件、实验文件和本地验收产物。
5. 公共版与私有版分别提交并推送到各自远端修复分支，再由维护者审查合并。不得把私有版完整提交直接推到公共仓库。
6. 保存两个提交标识、实际推送远端、测试结果与未完成的宿主验证。不要以“文件已复制”代替双方验收。

组件数量取决于各自WIDGET_COMPONENTS；私有版可以拥有额外组件，不应为了表面一致删掉私有功能或把它们意外公开。

临时验收项目含pnpm的目录链接。不要使用会遍历依赖链接的递归移动来归档整个项目；只归档源码、截图和报告，依赖交给包管理器重建。清理前核对实际路径与链接类型，避免影响工作区packages。
