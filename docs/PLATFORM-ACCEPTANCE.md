# 资源与平台验收

## 资源输入边界

- 图片：PNG、WebP、JPG/JPEG，扩展名大小写不敏感。JPEG原样复制，不做有损转码；PNG图集只处理PNG，其余图片继续单图发布。
- 音频：WAV、MP3；MP3可覆盖同名WAV。JSON保留扩展名作为逻辑键。
- 同名不同图片格式按包体择优；assets-pack同名图片覆盖assets。图片与音频的去扩展名逻辑键冲突时直接报错，不能让其中一个静默丢失。
- SVG/GIF/AVIF、PSD、字体、视频等未支持媒体不能直接放进资源目录；构建与dev会显示错误路径及转换提示。README、TSV/CSV等说明或配表源不作为媒体打包。
- 原图、草稿与样张放artifacts；assets只放运行时需要的最终文件。0字节文件仍按既有规则跳过并警告。
- dev同时监听assets与assets-pack，资源增删或覆盖会使虚拟清单与图集缓存失效并整页重载。

## 可自动执行的检查

仓库根：`pnpm run doctor`、`pnpm typecheck`、`pnpm test`、`pnpm lint`、`pnpm verify-platform`。
具体项目：`pnpm mg -- doctor --root games/<name>`，在项目目录执行`pnpm test`、`pnpm build`、`pnpm check`。
环境检查只检查仓库；指定项目时才校验游戏配置与三端入口。doctor不替代包体检查或平台测试。

浏览器平台门禁覆盖不同DPR、窄屏、真实点击、build/dev，以及主动破坏变换后的失败反例。
游戏仍需单独检查390×844与320×568截图、玩法与资源加载；根单测不覆盖games。

## 微信与抖音宿主验收

构建通过与宿主验收是两个独立状态。未运行对应宿主时，记录“未验证”，不可写成“三端已验证”。
每次发布记录：提交标识、应用标识、开发者工具版本、基础库版本、设备型号/系统、日期、截图或录屏位置。

在各自开发者工具导入build/wx、build/tt，再分别执行：

1. 清缓存冷启动，资源全部可见，日志无加载失败，主包不超限制。
2. 窄屏/长屏、刘海安全区与系统胶囊不遮挡操作；触摸位置与画面一致。
3. 首次触摸后音效可播放；静音、反复播放、暂停继续均符合游戏预期。
4. 单指/多指、滑出画布、触摸取消与连续操作后不残留按下状态。
5. 切后台再返回：游戏按设计暂停或恢复，音频不重叠，存档往返一致。
6. 如使用分包，分别验证成功、失败回落与重复进入。
7. 至少一台真机连续运行完整一局，检查帧率、内存增长与发热；开发者工具不能替代这一步。

报告分别列出web、微信工具、微信真机、抖音工具、抖音真机的状态与证据；没有执行的项目明确留空或记未验证。
